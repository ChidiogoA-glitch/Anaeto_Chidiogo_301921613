==========================================================================================
5. DATABASE CONSTRAINTS
==========================================================================================

Evidence for Portfolio 1: Database Design and Modelling, Hospital Management System (Miva
Hospital), PostgreSQL.

+------------+---------------------------------------+----------------------------------+
| Constraint | Applied to                            | Purpose                          |
+============+=======================================+==================================+
| PRIMARY    | All five tables                       | Ensures each record has a unique |
| KEY        |                                       | identifier.                      |
+------------+---------------------------------------+----------------------------------+
| FOREIGN    | Appointments, Prescriptions,          | Maintains relationships between  |
| KEY        | Laboratory_Records                    | tables.                          |
+------------+---------------------------------------+----------------------------------+
| NOT NULL   | Required fields                       | Prevents essential information   |
|            |                                       | from being left empty.           |
+------------+---------------------------------------+----------------------------------+
| UNIQUE     | Patients.email, Doctors.email         | Prevents duplicate email         |
|            |                                       | addresses.                       |
+------------+---------------------------------------+----------------------------------+
| DEFAULT    | Appointments.status                   | Sets new appointments to         |
|            |                                       | Scheduled.                       |
+------------+---------------------------------------+----------------------------------+
| DEFAULT    | Prescriptions.prescription_date       | Automatically records the        |
|            |                                       | current date and time.           |
+------------+---------------------------------------+----------------------------------+
| DEFAULT    | Laboratory_Records.result_status and  | Sets new records to Pending and  |
|            | test_date                             | records the current date and     |
|            |                                       | time.                            |
+------------+---------------------------------------+----------------------------------+
| CHECK      | Appointments.status                   | Restricts status to Scheduled,   |
|            |                                       | Completed or Cancelled.          |
+------------+---------------------------------------+----------------------------------+

CONSTRAINT NAMES IN THE POSTGRESQL SCHEMA
-----------------------------------------

+-------------------------------+-----------+-------------------------------------------+
| Constraint name               | Type      | Rule                                      |
+===============================+===========+===========================================+
| PK_Patients                   | PRIMARY   | patient_id                                |
|                               | KEY       |                                           |
+-------------------------------+-----------+-------------------------------------------+
| UQ_Patients_Email             | UNIQUE    | email                                     |
+-------------------------------+-----------+-------------------------------------------+
| PK_Doctors                    | PRIMARY   | doctor_id                                 |
|                               | KEY       |                                           |
+-------------------------------+-----------+-------------------------------------------+
| UQ_Doctors_Email              | UNIQUE    | email                                     |
+-------------------------------+-----------+-------------------------------------------+
| PK_Appointments               | PRIMARY   | appointment_id                            |
|                               | KEY       |                                           |
+-------------------------------+-----------+-------------------------------------------+
| FK_Appointments_Patients      | FOREIGN   | patient_id -> Patients(patient_id)        |
|                               | KEY       |                                           |
+-------------------------------+-----------+-------------------------------------------+
| FK_Appointments_Doctors       | FOREIGN   | doctor_id -> Doctors(doctor_id)           |
|                               | KEY       |                                           |
+-------------------------------+-----------+-------------------------------------------+
| CK_Appointments_Status        | CHECK     | status IN ('Scheduled', 'Completed',      |
|                               |           | 'Cancelled')                              |
+-------------------------------+-----------+-------------------------------------------+
| PK_Prescriptions              | PRIMARY   | prescription_id                           |
|                               | KEY       |                                           |
+-------------------------------+-----------+-------------------------------------------+
| FK_Prescriptions_Patients     | FOREIGN   | patient_id -> Patients(patient_id)        |
|                               | KEY       |                                           |
+-------------------------------+-----------+-------------------------------------------+
| FK_Prescriptions_Doctors      | FOREIGN   | doctor_id -> Doctors(doctor_id)           |
|                               | KEY       |                                           |
+-------------------------------+-----------+-------------------------------------------+
| FK_Prescriptions_Appointments | FOREIGN   | appointment_id ->                         |
|                               | KEY       | Appointments(appointment_id)              |
+-------------------------------+-----------+-------------------------------------------+
| PK_Laboratory_Records         | PRIMARY   | lab_id                                    |
|                               | KEY       |                                           |
+-------------------------------+-----------+-------------------------------------------+
| FK_LabRecords_Patients        | FOREIGN   | patient_id -> Patients(patient_id)        |
|                               | KEY       |                                           |
+-------------------------------+-----------+-------------------------------------------+
| FK_LabRecords_Doctors         | FOREIGN   | doctor_id -> Doctors(doctor_id)           |
|                               | KEY       |                                           |
+-------------------------------+-----------+-------------------------------------------+
| FK_LabRecords_Appointments    | FOREIGN   | appointment_id ->                         |
|                               | KEY       | Appointments(appointment_id)              |
+-------------------------------+-----------+-------------------------------------------+

PostgreSQL stores unquoted names in lowercase, so these appear as, for example,
pk_patients in \d patients output and in the verification query at the end of
schema/01_create_tables.sql.
