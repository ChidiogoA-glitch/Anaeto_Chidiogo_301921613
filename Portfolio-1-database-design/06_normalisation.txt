==========================================================================================
6. NORMALISATION EXPLANATION
==========================================================================================

Evidence for Portfolio 1: Database Design and Modelling, Hospital Management System (Miva
Hospital), PostgreSQL.

Database normalisation is the process of organising data into structured tables to reduce
duplication, prevent data anomalies and improve data integrity. The Hospital Management
System is designed to satisfy the first three normal forms: 1NF, 2NF and 3NF.

FIRST NORMAL FORM (1NF)
-----------------------

Requirement: Each column must contain atomic (single) values, each record must be uniquely
identifiable, and there must be no repeating groups or multiple values stored in one
field.

Application: The database satisfies 1NF because each table has a primary key and each
column stores a single value. For example, first_name and last_name are stored in separate
columns in Patients. Prescriptions are stored as individual records, allowing a patient to
receive multiple prescriptions without placing several medications in one field.

SECOND NORMAL FORM (2NF)
------------------------

Requirement: A table must satisfy 1NF, and every non-key attribute must depend on the
whole primary key, with no partial dependencies.

Application: Each table uses a single-column primary key. For example, the doctor's name,
specialisation, phone number and email depend on doctor_id in Doctors. Similarly, the
appointment date, reason, diagnosis and status depend on appointment_id in Appointments.
Since the primary keys are not composite, partial dependencies do not arise.

THIRD NORMAL FORM (3NF)
-----------------------

Requirement: A table must satisfy 2NF and have no transitive dependencies; non-key
attributes must depend on the key, the whole key and nothing but the key.

Application: Patient details, doctor details, appointment information, prescription
information and laboratory information are stored in separate tables. For example,
doctors' names and specialisations are stored in Doctors rather than repeatedly in
Appointments. Appointments stores doctor_id as a foreign key, allowing the doctor's
details to be retrieved when needed. Patient information is similarly stored once in
Patients and referenced through patient_id.

SUMMARY OF NORMALISATION
------------------------

+---------+------------------------+---------------------------------------------------+
| Normal  | Requirement            | How the database satisfies it                     |
| form    |                        |                                                   |
+=========+========================+===================================================+
| 1NF     | Atomic values and no   | Each column contains individual values and each   |
|         | repeating groups.      | table has a primary key.                          |
+---------+------------------------+---------------------------------------------------+
| 2NF     | No partial             | Each table has a single-column primary key, so    |
|         | dependencies.          | non-key attributes depend on the entire key.      |
+---------+------------------------+---------------------------------------------------+
| 3NF     | No transitive          | Patient, doctor, appointment, prescription and    |
|         | dependencies.          | laboratory information are separated into         |
|         |                        | appropriate tables.                               |
+---------+------------------------+---------------------------------------------------+
